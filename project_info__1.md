# Git Push Error — Analysis and Fix

## The Problem

The push is being rejected because GitHub detected a file exceeding 100 MB:

```
File: .next/dev/cache/turbopack/f37fad94/00000723.sst
Size: 195.55 MB
```

The `.gitignore` currently has `.next` on line 2, but that file was already tracked by git **before** `.next` was added to `.gitignore`. Once git has tracked a file, adding it to `.gitignore has no effect` — the file remains in git's index.

## Why `.next/` Should Never Be Committed

- `.next/` is a **build artifact cache** generated by Next.js during development and production builds
- It contains turbopack cache files (`.sst`), compiled JavaScript, server bundles, and more
- These files are machine-generated, can be hundreds of MB, and change every time you run `next build` or `next dev`
- They should **never** be pushed to GitHub

## The Fix

You need to remove `.next/` from git's tracking **without deleting the files from your disk**:

```bash
git rm -r --cached .next/
git commit -m "Remove .next/ from git tracking (should never have been committed)"
git push origin main
```

The `--cached` flag is critical — it tells git to stop tracking the files while leaving them on your filesystem.

## After the Fix

The `.gitignore` is already correct. Verify that `out/` is also not being tracked (it's in `.gitignore` as `out`, but may have been committed before the rule was added). You can check with:

```bash
git ls-files --cached | grep "^\.next\|^out"
```

If `out/` files appear, run the same `git rm -r --cached out/` command.

## Important

- This will require a force push? No, a normal commit + push will work fine since no history is being rewritten — just a new commit that removes the files.
- The large `.sst` file will still exist in your git history prior to this commit. To fully remove it from history, you'd need `git filter-branch` or `BFG Repo Cleaner`, but that's unnecessary for a basic fix. The current commit just stops it from being included *going forward*.
